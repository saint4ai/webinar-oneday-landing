# Промпт облачному агенту в GitHub: собрать все решения Александра в кейсы

## Перед запуском (сделать один раз, 2 минуты)

1. Создайте в GitHub пустой приватный репозиторий `saint4ai/business-cases`. Это «хаб»: агент складывает туда результат.
2. Откройте настройки приложения Claude в GitHub (Settings → Applications → Installed GitHub Apps → Claude → Configure) и дайте доступ **All repositories** для аккаунта `saint4ai` и для организаций `onaicademy` и `aoneagency001-maker`. Без этого облачный сеанс видит только репозиторий, в котором запущен.
3. Запустите новый облачный сеанс Claude Code на репозитории `saint4ai/business-cases` и вставьте блок ниже целиком.

Почему так: по документации Claude Code облачный сеанс работает в одном репозитории, а остальные читает через доступ приложения GitHub. Если в вашем тарифе есть «Проекты» (несколько облачных сеансов на одну задачу), можно раздать репозитории по сеансам, но хаб для результата всё равно один.

```
Ты собираешь портфолио Александра Saint (@saint4ai, основатель onAI Academy). Он разработчик без знаний программирования: с 2023 года внедряет ИИ в бизнес, с 2025 года собирает IT-решения для бизнеса вайбкодингом (ставит задачи агенту Claude Code, код пишет агент). Задача: найти во ВСЕХ его репозиториях решения для бизнеса и упаковать каждое в кейс. Результат пойдёт в автокарусель «Что я собрал для бизнеса» в презентации эфира и на страницы onai.academy/saint/cases/.

Ты работаешь в репозитории-хабе saint4ai/business-cases. Все остальные репозитории только читаешь: не коммить в них, не открывай в них PR и issues, не меняй приватность.

ШАГ 0. ДОСТУП. Выполни для каждого владельца: gh repo list saint4ai --limit 300 --json name,description,updatedAt,isPrivate,url (то же для onaicademy и aoneagency001-maker). Попробуй клонировать один приватный репозиторий каждого владельца в /tmp/src (git clone --depth 50). Если списка или клона нет, остановись и напиши Александру, какие владельцы недоступны и что в настройках приложения Claude в GitHub нужно включить All repositories. Токены и пароли не проси.

ЭТАЛОН ФОРМАТА. Готовые пакеты кейсов в репозиториях saint4ai/onai-academy-case, saint4ai/erickson-academy-case, saint4ai/the-one-system-case: README.md, CASE.md, FACTS.md, SCREENSHOTS.md, screenshots/. Прочитай все три целиком до начала. Эти кейсы и AI-Таргетолог (aoneagency001-maker/AI-targetolog, продукт https://app.aoneagency.kz, страница https://onai.academy/saint/cases/ai-targetolog/) не переупаковывай, только внеси в общий список. Если для AI-Таргетолога нет FACTS и CASE, собери их.

ШАГ 1. ИНВЕНТАРИЗАЦИЯ → INVENTORY.md в хабе. Таблица по каждому репозиторию: что это одной строкой; для кого (ниша клиента или свой продукт); статус (прод / пилот / демо / заброшен); живая ссылка, если есть в README, package.json, конфиге деплоя; даты первого и последнего коммита; решение для бизнеса или нет (служебные скрипты, форки, эксперименты, курсы, личные настройки — «нет»). Сгруппируй решения: платформы обучения, CRM и аналитика, боты и ИИ-менеджеры, сайты и лендинги, автоматизации, внутренние сервисы.

ШАГ 2. СОГЛАСОВАНИЕ. Закоммить INVENTORY.md и напиши Александру в этом сеансе список кандидатов: номер, название, одна строка, статус. Он отметит, что упаковывать и что нельзя показывать (имена клиентов, закрытые проекты). Без его ответа к шагу 3 не переходи.

ШАГ 3. ПАКЕТЫ. По каждому одобренному решению папка cases/<slug>/ как в эталоне:
- README.md: задача кейса, читатель, карта папки.
- CASE.md: блоки «задача → решение → как работает → результат было/стало». Один блок одна мысль, заголовок блока несёт вывод.
- FACTS.md: каждая цифра с источником (файл и коммит, README, живая страница, слова Александра с датой). Непроверенное помечай «нет»: на страницу не выносится.
- SCREENSHOTS.md: список нужных кадров (URL или экран, что должно быть видно, размер 1440×900, для телефона 390×844, что размыть).
- screenshots/: попробуй снять живые публичные страницы безголовым браузером (npx playwright install chromium, затем скрипт). Если браузер в среде не запускается, кадры не подделывай и не рисуй: оставь список в SCREENSHOTS.md, их снимет локальная сессия. Персональные данные, названия клиентов без разрешения, ключи и .env в кадр не попадают.

ШАГ 4. СВОДКА → cases.json в корне хаба, массив:
{ "slug", "title", "niche" (без имени клиента, если не разрешено), "one_liner" (до 9 слов, результат для бизнеса), "what" (до 15 слов), "metric" (одна проверенная цифра с подписью или null), "metric_source", "status" ("прод" | "пилот" | "демо"), "period" ("08.2025–10.2025"), "stack_note", "screenshot" (путь к главному кадру или null), "screenshot_todo" (что снять, если кадра нет), "case_url" (страница кейса или null), "public" (можно ли показывать на эфире) }.

ШАГ 5. ОТЧЁТ → REPORT.md: сколько репозиториев просмотрено, сколько решений найдено и упаковано, что не проверено, какие кадры осталось снять, вопросы Александру. Коммить в ветку cases/harvest хаба и открой один PR в хабе.

ПРАВИЛА: факты только из источников, клиентов и цифры не придумывать; тексты по-русски, коротко, без длинных тире и штампов; на серверы не заходить и ничего не деплоить; если не уверен, спроси Александра.
```
