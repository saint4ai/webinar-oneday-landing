# ТЗ: свои WhatsApp-группы эфира вместо EasyBot (08.10.2026)

Рабочая папка `C:\Проекты\wt-wa` (git worktree, ветка `feat/wa-groups` от воронки). Не коммитить, не пушить, на сервер не выкладывать: это делает Opus. Ничего не отправлять в настоящий WhatsApp.

## Зачем

Александр хочет отказаться от EasyBot. Каждый день в 20:00 по Алматы должна автоматически создаваться новая WhatsApp-группа под следующий эфир. Группа собирает людей с 20:00 до 00:00 следующего дня. В неё по расписанию уходит прогрев, как сейчас вручную шлёт модератор по таблице. Отправка идёт с отдельного номера, подключённого по QR, через Evolution API на нашем сервере.

Разбор с рисками лежит в истории сессии. Коротко:
- Evolution API работает через протокол WhatsApp Web, это неофициальный канал. Номер могут заблокировать, поэтому подключаем только отдельную прогретую SIM;
- официальные группы Meta ограничены 8 участниками и не подходят;
- Communities в Evolution нет, работаем с обычными группами до 1024 человек.

## Архитектура

1. **Evolution API v2.3.7.** Ставим без Docker. Версию 2.4 не берём: там обязательная активация и телеметрия.
   - На сервере Ubuntu уже есть Node, PostgreSQL на 127.0.0.1:5432 и Redis на 127.0.0.1:6379, Docker не установлен.
   - Свободно около 7 ГБ диска и 2,7 ГБ памяти, 4 ядра.
   - Нужен скрипт установки `scripts/install-evolution.sh` (запуск от root, повторный запуск безопасен):
     - клон тега 2.3.7 в `/opt/evolution`, `npm ci`, сборка;
     - отдельная база и пользователь в PostgreSQL, Redis с отдельным префиксом или номером базы;
     - `.env` с `SERVER_URL=http://127.0.0.1:8080`, случайным `AUTHENTICATION_API_KEY` (генерировать на сервере, в репозиторий не писать), только локальный порт;
     - миграции Prisma, запуск через pm2 под пользователем `onaiapp`, имя процесса `evolution`;
     - проверка `GET /` и вывод итога; откат одной командой (pm2 delete, база остаётся).
   - Переменные `.env` и команды сборки сверь с исходниками тега 2.3.7 на GitHub (EvolutionAPI/evolution-api), не по памяти.
2. **Модуль в form-api.** Новые файлы `form-api/wa-evolution.ts` (клиент), `form-api/wa-groups.ts` (логика), `form-api/wa-series.json` (расписание).
   - Подключение в `server.ts` под флагом `WA_GROUPS=on`; без флага ничего не запускается и не ломается.
   - Тик общий с планировщиком Telegram или свой, раз в 30 с.
   - Состояние храни в `/opt/workshop-form/data` (JSON), как `tg-state.json`.

## Логика групп

- **День эфира D**, эфир в 20:00 по Алматы, как в `tg-time.ts` и `assignStreamDay`.
- **В 20:00 дня D-1** создаётся группа эфира D:
  - название «Вайб-продакшен · эфир DD.MM»;
  - описание короткое, без цены;
  - аватарка: обложка `workshop-montazh/assets/tg/cover-bizon.jpg`, обрезать в квадрат;
  - режим «пишут только админы» (announcement);
  - в участники и админы сразу добавить номер менеджера Аяны из `WA_ADMIN_NUMBERS` (env, через запятую). Это нужно и для создания группы, если пустую WhatsApp не создаёт;
  - сохранить JID и ссылку-приглашение.
- **Текущая ссылка.** С 20:00 дня D-1 `/workshop/api/whatsapp-link` отдаёт ссылку группы эфира D. Сейчас этот маршрут отдаёт постоянную ссылку сообщества, найди его в `server.ts`. Если модуль выключен или группы нет, отдаётся старая ссылка, как сейчас.
- **Переполнение.** При 1000 участниках и больше создать следующую группу того же эфира «(2)» и переключить ссылку на неё. Число участников проверять не чаще раза в 5 минут.
- **Прогрев.** Сообщения по `wa-series.json` уходят во все группы эфира D:
  - собери файл из секции `whatsapp` в `docs/mailings/chain-v2.json`: время, текст, картинка, опрос;
  - картинки по адресу `https://onai.academy/workshop-montazh/assets/tg/<файл>`;
  - опрос 11:30 «Придёшь сегодня на эфир?» через sendPoll, варианты возьми из колонки «Что сделать ещё» в chain-v2.
  - Сообщения дня эфира идут по времени дня D. Если группа создана в 20:00 D-1, ей до утра D ничего не шлём, кроме приветствия при создании (короткий текст: что это за группа и когда эфир).
- **После 00:00 дня D+1** группа закрыта для рассылки, ссылка уже на группе следующего эфира.

## Защита номера (обязательно)

- **Без личных сообщений и без добавления людей.** Никаких сообщений людям в личку и никакого добавления участников, кроме номеров из `WA_ADMIN_NUMBERS`. Люди входят только по ссылке.
- **Темп отправки.** Между отправками в разные группы пауза 4–9 с со случайным разбросом. Не больше 3 новых групп в сутки. Всё последовательно, без параллельных запросов к Evolution.
- **Повторные попытки.** Повтор с паузой. После 3 неудач подряд модуль встаёт на паузу и шлёт тревогу владельцам в Telegram через существующего бота, как отчёты (`TG_LINK_OWNER_IDS`).
- **Нет подключения.** Если `connectionState` не open, ничего не отправлять, тревога в Telegram раз в час, не чаще.
- **Журнал.** Каждая отправка: время, группа, id сообщения, итог. Токены и ключи в журнал не писать.

## Управление из Telegram-бота (только владельцы)

Команды в существующем боте воркшопа (`tg-workshop.ts`, как `/stats`, `/off`, `/on`):
- `/wa`: состояние подключения, номер, группы текущего и следующего эфира, участники, ближайшее сообщение, пауза или нет.
- `/wa_qr`: создать инстанс, если его нет, получить QR и прислать владельцу картинкой; повторно не чаще раза в минуту.
- `/wa_pause` и `/wa_resume`.
- `/wa_new`: создать группу следующего эфира вручную сейчас.
- `/wa_send <id>`: отправить сообщение серии в группы текущего эфира вручную.

## Тесты

В стиле `form-api/tg.test.ts`:
- подставной Evolution на локальном порту;
- создание группы в 20:00;
- переключение ссылки;
- переполнение;
- отправка по расписанию с паузами (время подменять, без реального ожидания);
- пауза после ошибок;
- без подключения ничего не уходит;
- команды владельцев;
- без `WA_GROUPS=on` модуль не стартует.

Все старые тесты должны проходить. Запуск: junction `node_modules` на `C:\Проекты\wt-main\node_modules`, `npx --yes tsx --test form-api/*.test.ts`, после прогона junction убрать.
