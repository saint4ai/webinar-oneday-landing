# Админка воркшопа как Telegram Mini App (только для Александра, пароль)

Задание Opus от 07.10.2026. Слова Александра: «сделай мне Telegram App прямо в моём Telegram, конкретно для моего Telegram ID, чтобы я открывал приложение, вводил пароль 153 и входил в админку, где мог бы видеть все регистрации, аналитику и прочие данные».

Рабочая папка `C:\Проекты\wt-funnel` (ветка fix/lead-redirect-whatsapp), код `form-api/`. Бот уже на проде, админ-отчёты в чате (`tg-admin.ts`) работают: их не ломать, переиспользовать их функции подсчёта. Не коммитить, не деплоить, не ходить на сервер, порты 3000–3003 не трогать.

## Доступ (всё обязательно)
1. Приложение открывается только из Telegram: каждый запрос к данным проверяет `initData` Telegram WebApp по официальной схеме (secret_key = HMAC_SHA256(key "WebAppData", msg = токен бота); hash = hex HMAC_SHA256(secret_key, data_check_string), data_check_string = пары `key=value` кроме `hash`, отсортированные по ключу, через `\n`; `auth_date` не старше 24 часов). Сравнение за константное время.
2. `user.id` из initData должен быть в `ADMIN_APP_IDS` (env, по умолчанию `789638302`, это Александр). Другим 403 без подробностей.
3. Пароль: env `ADMIN_APP_PIN` (на сервере будет 153; в код и репозиторий не писать, в тестах свой). После верного пароля сервер выдаёт сессию: подписанный HMAC токен (отдельный секрет `ADMIN_APP_SECRET`, user.id, срок 12 часов), хранить в `sessionStorage` мини-приложения. Ошибки пароля: не больше 5 попыток за 10 минут на user.id, дальше 429.
4. Все ответы с данными `Cache-Control: no-store`. В логах ни пароля, ни initData, ни телефонов.

## Где живёт
- Страница: `GET /api/admin-app` отдаёт один HTML (файл `form-api/admin-app.html` рядом с бандлом, читать через fs из `__dirname`, как tg-series.json). Снаружи `https://onai.academy/workshop/api/admin-app` (nginx уже проксирует `/workshop/api/` на form-api). Скрипт Telegram: `https://telegram.org/js/telegram-web-app.js`. CSP на ответе: только свой origin и telegram.org.
- Данные: `POST /api/admin/login` (initData + pin → token), `GET /api/admin/summary?from=&to=`, `GET /api/admin/leads?from=&to=&q=&utm=&inbot=`, `GET /api/admin/subscribers?...`, `GET /api/admin/errors?...`. Токен в заголовке `Authorization: Bearer`, initData в заголовке `X-Tg-Init-Data` на каждом запросе.
- Кнопка в боте только у Александра: `setChatMenuButton` с `chat_id` из `ADMIN_APP_IDS`, тип `web_app`, текст «Админка», url страницы. Добавить шаг в `tg-setup.ts` (и отдельную команду владельца `/app`, которая присылает сообщение с inline-кнопкой web_app на ту же страницу). Другим пользователям кнопка не ставится.

## Что внутри (мобильный экран, тема Telegram: `themeParams`, светлая и тёмная; бренд onAI: золото как акцент)
1. **Вход:** логотип, поле пароля (цифровая клавиатура), кнопка «Войти», ошибка «Неверный пароль, осталось N попыток».
2. **Шапка:** выбор периода: Сегодня, Вчера, 7 дней, 30 дней, «Даты» (два поля даты); переключатель день эфира/день регистрации, где это имеет смысл. Кнопка обновить. Часовой пояс Алматы.
3. **Сводка:** карточки: заявки с сайта, в боте новых, доля заявка → бот, нажали WhatsApp и Telegram после заявки, перешли на эфир, «Я уже оплатил(а)», заблокировали бота. Для каждого сравнение с прошлым таким же периодом (стрелка и разница).
4. **По дням:** столбчатый график заявок по дням и линия «в боте» (простой SVG без библиотек или маленькая библиотека с cdnjs). Под ним таблица.
5. **Источники:** таблица UTM (`utm_source / utm_medium / utm_campaign`): заявки, дошли до бота, доля; «без метки» по referrer; метки бота вне сайта (`2gis` и т.п.). Нажатие на строку фильтрует список регистраций.
6. **Регистрации:** список заявок за период: время, имя, телефон (нажатие копирует), место на странице, UTM, в боте или нет. Поиск по имени или телефону, фильтры по UTM и «в боте / не в боте». Подгрузка по 50.
7. **Подписчики бота:** список за период: время, имя, @username, откуда (окно, страница, прямой /start, метка), день эфира, перешёл на эфир, оплатил, заблокировал.
8. **Эфиры:** по дням эфира: записались, перешли, %, оплатили; какие сообщения серии ушли (отправлено и ошибки).
9. **Ошибки:** как экран «Ошибки» в чате плюс время работы и версия.
Тексты интерфейса по-русски, без длинного тире. Большие таблицы прокручиваются внутри своего блока, страница по ширине не прокручивается (ширина 360–430 px).

## Тесты
