# Бот @workshop_aiprod_bot: админ-панель, аналитика по датам и UTM, ежедневный отчёт

Задание Opus от 07.10.2026. Слова Александра: «Нужно сделать меня администратором в этом боте, чтобы я видел статистику: сколько пользователей зарегистрировалось в боте за выбранную дату. Добавь удобные фильтры, аналитику и ошибки. Затем сделай так, чтобы ежедневная аналитика приходила мне в бот. Также нужно отслеживать UTM-метки, чтобы было видно, откуда пришли пользователи: из 2GIS или рекламных кампаний. По UTM-меткам тоже должна быть аналитика по датам.»

Код: `form-api/tg-*.ts`, `form-api/server.ts` (ветка fix/lead-redirect-whatsapp, рабочая папка `C:\Проекты\wt-funnel`, другие папки не трогать). Владельцы уже есть: `TG_LINK_OWNER_IDS` (Александр 789638302 там). Не коммить, не деплоить, не ходить на сервер, порты 3000–3003 не трогать.

## Данные (всё уже пишется)
- Заявки с сайта: `LEADS_LOG_PATH` из `.env` (на сервере `/var/lib/workshop/leads.jsonl`), строки `{kind,id,eventId,name,phone,source,utm,ts}`; `utm` = объект `utm_source, utm_medium, utm_campaign, utm_content, utm_term, gclid, utm_referrer`. Сейчас по факту: `instagram | paid_social | efir_0710`, `saint4aibio`, у многих utm нет, но есть `utm_referrer` (instagram.com, l.instagram.com). Источник места на странице: `source` = `efir-1-okt-hero|dock|header|final|popup`.
- Бот: `data/tg-subscribers.jsonl` (start с `payload`: `pp_<eventId>` из окна на сайте, `ty_<eventId>` со «Спасибо», пусто для прямого /start, любой другой payload вроде `2gis` = метка источника), `tg-sent.jsonl`, `tg-clicks.jsonl`, `ty-clicks.jsonl`.
- Связка бот ↔ заявка: `payload` после `pp_`/`ty_` = `eventId` заявки → её utm.

## Что сделать

### 1. Меню админа `/admin` (и `/stats` открывает то же)
Только владельцам; чужим молча ничего (и на callback тоже только `answerCallbackQuery`). Кнопки периода: «Сегодня», «Вчера», «7 дней», «30 дней», «Дата…» (вторая клавиатура: последние 14 дней кнопками `дд.мм` + «Весь период»). Дни считать по Алматы (UTC+5, как в tg-time.ts).

Отчёт за период (одно сообщение, HTML, без имён и телефонов, только числа):
- **Заявки с сайта:** всего; по дням (если период больше дня); по месту на странице (hero, popup, dock…); по UTM (`utm_source / utm_medium / utm_campaign`, топ-8, остальное «прочие»); без UTM разбить по сайту-источнику из `utm_referrer` (instagram.com, l.instagram.com, прямой заход).
- **Бот:** новые подписчики за период (по первому /start); откуда: окно на сайте (pp), «Спасибо» (ty), прямой /start, другие метки (2gis и т.п.); по UTM через связку с заявкой; доля «заявка → бот» (сколько заявок периода дошли до бота).
- **Кнопки после заявки:** WhatsApp и Telegram (ty-clicks), с разбивкой окно/страница, если есть поле src.
- **Эфиры периода:** по каждому дню эфира: записались в бота, перешли по кнопке эфира, %, «Я уже оплатил(а)».
- **Рассылка:** отправлено по сообщениям, ошибок, заблокировали бота.
Под отчётом кнопки: «UTM по дням», «Ошибки», «Обновить», «← Период». Отчёт редактирует то же сообщение (`editMessageText`), не плодит новые.

### 2. «UTM по дням»
Таблица за выбранный период: строки = дни, колонки = топ-4 источника (`utm_source`, пусто = «без метки») по заявкам и в скобках сколько из них дошли до бота. В `<pre>`, ширина колонок ровная, ≤ 4096 символов (иначе обрезать дни с пометкой).

### 3. «Ошибки»
За период: неудачные отправки (по тексту ошибки, счётчики; последние 10 с временем и id сообщения серии, без чата и имён), заблокировали бота, пропуски по опозданию планировщика, подмены медиа на текст, отказы вебхука по секрету (счётчик в памяти с момента запуска), время работы процесса и версия (`VERSION`).

### 4. Ежедневный отчёт админам
Каждый день в `adminDailyReportAt` из `tg-series.json` (по умолчанию "09:00" по Алматы) за вчерашний день: тот же отчёт, что «Вчера», компактно, плюс топ UTM и строка про ошибки. Отметка в `tg-state.json` (не дублировать после рестарта, не догонять пропущенные дни старше суток). От `seriesEnabled` не зависит. Отчёт после эфира в 21:25 остаётся как есть.

### 5. Метки источников для ссылок вне сайта
Любой payload, который не `pp_…`/`ty_…`, считать меткой источника (до первого `_`), например `t.me/workshop_aiprod_bot?start=2gis`. В отчётах показывать его как источник.

### 6. `/help` для владельца
Список команд одной короткой справкой: /admin, /series, /preview, /fire, /at, /off, /on, /bizon, /paid, /reload, /series_on, /series_off.

### 7. Производительность и надёжность
Чтение файлов заявок и событий с кешем по mtime и размеру (не перечитывать на каждое нажатие). Ошибка чтения файла заявок не роняет бота: в отчёте строка «заявки недоступны». Все тексты без длинного тире.

### 8. Тесты (node:test, как tg.test.ts)
Границы дней по Алматы (23:59/00:00, TZ=UTC и America/Los_Angeles), связка pp_/ty_ с eventId, группировка UTM и «без метки» по referrer, метка 2gis, длина сообщений ≤ 4096, кнопки только для владельцев, ежедневный отчёт один раз в сутки и после рестарта. Пересобрать `form-api/dist/server.js`.

Отчёт: коротко по-русски, что сделано, тесты, пример текста отчёта за «Сегодня» на тестовых данных.
